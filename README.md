# 企业微信需求看板（演示版）

一个运行在本机的网页看板：把消息中的待办需求集中展示，支持标记完成、按时间范围补录历史消息，以及把原始图片附在需求旁。文字可交给 DeepSeek 或其他兼容 OpenAI 接口的模型生成简短摘要；图片不会送给模型解读。

## 运行条件

- Node.js 18 或更高版本。项目本身没有第三方 npm 依赖。
- 使用企微数据时，安装并授权[企业微信官方 CLI](https://github.com/WecomTeam/wecom-cli)：`npm install -g @wecom/cli`、`wecom-cli auth init`，再用 `wecom-cli auth show --status` 确认输出 `authorized`。
- 企微业务权限需另行开通；CLI 显示 `authorized` 只表示登录成功。

## 启动

先复制 `.env.example` 为 `.env`。只看界面时保留 `WECOM_SOURCE=demo`，然后在项目目录执行：

```powershell
npm start
```

浏览器打开 `http://127.0.0.1:3210/`。如 3210 被占用，服务会尝试 3211；终端会显示实际地址。关闭该终端可停止这次启动的服务。

Windows 下也可以双击 `启动需求看板.bat`。该脚本会检查企微 CLI 登录状态、停止占用看板端口的旧 Node 进程、后台启动服务并打开浏览器，因此适合已配置企微 CLI 的本机使用。

## 接入企业微信

1. 在 `.env` 中设置 `WECOM_SOURCE=cli`，重启看板。
2. 要在页面“监控私聊”里按姓名搜索并添加联系人，**当前机器人必须获得「通讯录」使用权限**。由智能机器人创建者在企业微信「工作台 → 智能机器人」中为对应机器人授权。缺少该权限时，联系人搜索可能返回 `850002 no authorization`。这里的通讯录权限用于搜索联系人，不能代替聊天读取权限。
3. 页面通过 `chat groups list` 查找有消息的群聊，再通过 `chat messages list` 拉取群聊及已添加联系人的消息。官方接口只支持最近 7 天的时间范围；历史补录请选该范围内的时间。群聊查询在当前实现中先于私聊查询执行，因此群聊接口失败也会阻止私聊补录。
4. 自动监听还需设置 `WECOM_SELF_MESSAGE_USERID`，用于排除自己发出的消息。应填写 **`chat messages list` 返回的自己消息的 `userid` 原值**；不要使用通讯录搜索返回的 `userid` 代替。未设置时自动监听不会导入消息，但仍可手动尝试历史补录。

如果 `chat groups list` 返回 `853006 this tool is not available for your corporation`，说明当前企业无法使用该查询工具；重新登录或仅授权通讯录不能解决这个错误，需要向企业微信确认聊天读取能力是否对该企业开放。把机器人加入群聊，也不等于获得读取群历史消息的权限。本项目当前使用 CLI 定时拉取，没有接入智能机器人的实时消息回调；它不会自动读取所有发给你个人账号的私聊。

## 模型与数据

网页右上角“模型设置”可以填写接口地址、模型名和 API Key，并点击“测试连接”。配置保存在本机 `.env`；未配置密钥时，需求以原文字显示。测试连接会向填写的模型接口发送一条简短的 `ping` 请求。

需求状态保存在 `data/board.json`，下载的图片保存在 `data/media/`。`.env` 和 `data/` 已被 Git 忽略，请勿把真实密钥或聊天数据复制进源码文件。标记为“已完成”的需求不会因重复导入同一条消息重新进入待处理列表。历史补录会先显示候选消息，由你选择需要导入的需求。

运行测试：

```powershell
npm test
```
